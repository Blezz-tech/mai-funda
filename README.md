# Отчёты в Typst — МАИ, каф. 806, «Фундаментальная информатика»

Отчёты по лабораторным работам, перенесённые из ODT-файлов в Typst.
Папка называется по варианту, номер работы берётся из `main.typ`:

| Папка | `number:` | Отчёт |
|---|---|---|
| `lr/2/` | `"1 (2)"` | Лабораторная работа № 1 — операционная среда ОС UNIX |
| `lr/5/` | `"2 (5)"` | Лабораторная работа № 2 — программирование машин Тьюринга |
| `lr/9/` | `"5 (9)"` | Лабораторная работа № 5 — системы программирования на языке Си |
| `lr/template/` | `"x (y)"` | образец для новой работы, в сборку не попадает |

## Сборка

```bash
./build.sh                  # собрать всё -> dist/Лабораторная работа 1.pdf, …
./build.sh check            # только проверки, без typst
( cd lr/2 && typst compile --root ../.. main.typ out.pdf )   # по одной работе
```

`build.sh` находит все `**/main.typ` (кроме `*/template/*` — это образец
для новой работы, а не отчёт), берёт номер работы из самого файла
(`#report(number: "1")`, у ЛР 2 там `"2 (8)"` — номером считается первое
число) и кладёт результат в `dist/Лабораторная работа <номер>.pdf`.
Дубли номеров, отсутствие `number:` и ссылки на несуществующие файлы
(`#console("/lr/2/src/…")`, `image("/lr/2/img/…")`) — ошибка сборки, а не
тихо перезаписанный файл. Все проблемы печатаются сразу, до компиляции.

```bash
./build.sh check            # только проверки (ссылки, номера, дубли), typst не нужен
```

Этим же режимом CI/CD начинают работу: опечатка в пути валит сборку за
секунду и с понятным текстом, а не в середине установки шрифтов.
Сводка по сборке печатается в консоль и в `dist/summary.md`.

Нужен только `typst` (0.13+; проверено на 0.15.x). Если CLI нет в PATH,
установите его (`cargo install typst-cli`) или используйте Python-пакет
`typst` (`pip install --user typst`, `typst.compile(...)`).
`--root ..` обязателен, потому что шаблон лежит на уровень выше.

## CI/CD (GitHub Actions)

Тот же `./build.sh` запускается в GitHub Actions — локальная и серверная
сборки не расходятся. Всё бесплатно: репозиторий публичный (Actions для
публичных репозиториев без лимита минут), используются только официальные
`actions/*` и системные утилиты, никаких платных сервисов.

| Файл | Когда срабатывает | Что делает |
|---|---|---|
| `.github/workflows/ci.yml` | каждый push в `main`/`master`/`dev`, каждый PR, вручную | `./build.sh check`, затем сборка PDF; артефакт `laboratornye-raboty`, таблица в Summary |
| `.github/workflows/release.yml` | push тега `v*` | обычный релиз (Latest) с вложенными PDF |
| | push в `main`/`master` | релиз-сборка на этот коммит: тег `build-ГГГГММДД-ЧЧММ-<sha>`, prerelease (Latest не переключается) |
| | вручную (`Run workflow`) | то же, что push в текущую ветку |
| `.github/actions/build-reports/action.yml` | — | общий шаг: `./build.sh check`, Typst нужной версии, шрифты, `./build.sh` |

Оба workflow запускаются на `ubuntu-24.04` (явно, а не `ubuntu-latest`,
чтобы смена LTS в образе не ломала сборку неожиданно). Каждый шаг
установки — отдельный шаг в логе, поэтому по красному крестику сразу
видно, что именно упало: Typst, базовые шрифты, Times New Roman или
сама сборка.

К релизу прикладывается:

* `lab-reports.zip` — архив, внутри файлы с ровно теми именами, что в
  `dist/`: `Лабораторная работа 1.pdf`, `Лабораторная работа 2.pdf`, …;
* `lab-1.pdf`, `lab-2.pdf`, … — те же PDF отдельными файлами (GitHub
  переписывает имена ассетов релиза в ASCII, поэтому кириллическое имя
  сохраняется только внутри архива и в подписи ассета);
* `summary.md` — таблица собранных работ;
* в теле релиза-сборки — та же таблица из `dist/summary.md`.

Ручной релиз:

```bash
git tag v1.0 && git push origin v1.0     # -> GitHub Release v1.0 с PDF
```

Что где настраивается:

* версия Typst — `inputs.typst-version` в `.github/actions/build-reports/action.yml`
  (сейчас `v0.15.1`, качается официальный статический бинарник);
* шрифты — там же: `fonts-hack` (консоль), `fonts-liberation` (запасные
  метрические аналоги), `fonts-dejavu-core` и **настоящий Times New Roman**
  из `ttf-mscorefonts-installer` (multiverse, EULA принимается через
  `debconf-set-selections`, 3 попытки скачивания с SourceForge, между
  попытками `dpkg --configure -a`). Шаг «Проверить шрифты» падает, если в
  `typst fonts` нет `Hack`, `Liberation Serif` или `Liberation Mono` —
  иначе Typst молча подставит встроенный и вёрстка разъедется;
  Times New Roman по умолчанию обязателен
  (`inputs.require-times-new-roman: "true"`), с `"false"` его отсутствие
  даёт предупреждение, а текст набирается метрически совместимым
  Liberation Serif;
* релизы на каждый коммит в основную ветку — это работа `release` в
  `release.yml`; не нужны — уберите `branches:` из триггера `push`, и
  релизы будут только по тегам.

## Структура

```
lib/lab.typ     шаблон только для лабораторных работ:
                страница, шрифты, шапка ЛР, report() — весь каркас пунктов 1–11,
                console() — текст из .txt (консоль, листинг, тесты),
                общие списки оборудования и ПО (default-equipment / default-software)
lr/2/ lr/5/ lr/9/ main.typ (только содержимое отчёта) + src/ + img/ + tests/
lr/template/    образец main.typ для новой работы (в сборку не попадает)
```

`main.typ` каждой работы — это один вызов `report(...)`: в файле работы
лежат только отличия — номер, тема, цель, задание, содержимое пунктов 6–8 и
строки дневника отладки. Номера пунктов, их названия, пояснения в
скобках, оборудование, ПО, списки «Допущен к выполнению работы»,
«Пункты 1–7 отчета составляются строго до начала лабораторной работы.»
и подпись живут в шаблоне.

## Как написать новую работу

```typst
#import "/lib/lab.typ": setup, report, console

#show: setup.with()

#report(
  number: "3",
  topic: [Тема работы.],
  goal: [изучение и освоение …],
  task: [(вариант № 1) …],
  // необщие строки ПО — к общему списку (по желанию):
  software-extra: (
    "Утилиты операционной системы: nam",
  ),
  idea: [
    #console("/lr/3/src/commands.txt")
  ],               // содержимое пункта 6
  scenario: […],   // содержимое пункта 7
  protocol: [       // содержимое пункта 8
    *Сессия 1.*
    #console("/lr/3/src/session1.txt")
  ],
  diary-rows: (
    ("1", "дом.", "16.09.2025", "20:00", "Выполнение работы", "Нет", "Нет"),
  ),
  conclusion: […], // содержимое пункта 11
)
```

Общее ПО (`NixOS 26.11`, `zsh 5.9.2`, `gcc 16.2.0`, `vscode 1.144.0`) и
оборудование (`Процессор Intel® Core™ i5-12400F`, `ОП 32 ГБ`, `SSD 1 ТБ`,
`Монитор 23.8" AOC 24G2SAE/BK черный`) меняются в одном месте —
`lib/lab.typ` (`default-equipment` / `default-software`).

## Как что оформляется

| Элемент | В Typst |
|---|---|
| Поля 3 / 1.5 / 2 / 2 см, A4, 12 pt, нумерация | `setup(...)` из `lib/lab.typ` |
| Вся структура отчёта (пункты 1–11) | `#report(...)` в `main.typ` |
| Шапка лабораторной (заголовок + реквизиты) | внутри `report()` |
| Текст из `.txt` (консоль, листинг, тесты) | `#console("/lr/1/src/session1.txt")` |
| Картинка с подписью | `#figure(image("/lr/1/img/plot2d.png", width: 78%), caption: […])` |

Консоль, тесты и исходники — это просто `.txt`-файлы, скопированные из
терминала как есть. Никаких функций вида `test-case(...)` с массивами
строк и ручных отступов `#h(...)`: файл подключается одной строкой
`#console(...)` и печатается моноширинным шрифтом на светло-сером фоне —
как скопировано из консоли. Длинные строки переносятся по правому краю.

Текст отчётов лежит отдельно от оформления: чтобы поменять поля, кегль
или шрифт — правится один файл `lib/lab.typ`, тексты не трогаются.
То же самое работает и для общих блоков: название любого пункта,
оборудование и ПО меняются один раз в `lib/lab.typ`.

## Шрифты

В репозитории шрифтов больше нет — `typst` берёт их из системы.
Текст набирается **Times New Roman** (как в ODT-исходниках); в `setup()`
заданы цепочки с автоматической подстановкой — первая найденная гарнитура
используется, так что на машинах без MS-шрифтов подставится метрически
совместимый Liberation Serif (именно его LibreOffice сам подменяет вместо
Times New Roman в ODT):

* основной текст: `Times New Roman` → `Liberation Serif` → `Tinos` → `DejaVu Serif`;
* консоль: `Hack` → `Liberation Mono` → `Cousine` → `DejaVu Sans Mono`.

Цепочки лежат в `lib/lab.typ` (`default-body-font` / `default-mono-font`);
чтобы поменять гарнитуру или порядок — правятся они или параметры `setup()`
(`body-font:` / `mono-font:`). Если ни одно семейство из цепочки не найдено,
`typst` подставит свои встроенные шрифты (другой рисунок и толщина) —
в таком случае установите MS-corefonts (`ttf-ms-fonts` / `ttf-mscorefonts-installer`)
или croscore (`ttf-croscore`: Tinos/Cousine), либо `Hack`. В CI это
делается автоматически (см. раздел CI/CD), так что PDF из релиза
набраны настоящим Times New Roman.

## Что поправлено по сравнению с ODT

* длинные строки протоколов больше не уезжают за поле (в ODT они
  переносились как попало);
* списки оборудования/ПО — настоящие списки, а не табы;
* в ЛР 1 управляющие последовательности терминала (`^[[?2027...`) в одной
  строке протокола вычищены — осталась нормальная команда `cat f2.txt`;
* исправлены опечатки: «Тюрингита» → «Тьюринга», «Не нормированные
  алгоритм» → «Ненормированный алгоритм», «полиндромию» → «палиндром»
  (в ЛР/курсовых, где встречалось), «в пунке» → «в пункте», «Hellow world»
  оставлено как в исходнике (это вывод программы);
* в дневнике отладки ЛР 1 поправлена противоречивая запись про номер
  группы (в ODT было «не 133, а 133»).
