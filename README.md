Отчёты перенесены из ODT-файлов в Typst: текст каждой работы отдельно от
оформления, сборка одной командой, готовые PDF — в релизах. Папка работы
называется по варианту, номер работы берётся из самого `main.typ`:

| Папка | `number:` | Отчёт |
|---|---|---|
| `lr/2/` | `"1 (2)"` | № 1 — операционная среда ОС UNIX |
| `lr/5/` | `"2 (5)"` | № 2 — программирование машин Тьюринга |
| `lr/9/` | `"5 (9)"` | № 5 — системы программирования на языке Си |
| `lr/template/` | `"x (y)"` | образец для новой работы, в сборку не попадает |

## Быстрый старт

Нужен только [`typst`](https://github.com/typst/typst/releases) (0.13+,
в CI — 0.15.1) в `PATH`; шрифты берутся из системы.

```bash
git clone https://github.com/Blezz-tech/mai-funda && cd mai-funda
./build.sh
# dist/Лабораторная работа 1.pdf, dist/Лабораторная работа 2.pdf, …
```

`build.sh` только компилирует: находит все `**/main.typ` (кроме
`*/template/*`), читает номер работы из `#report(number: "…")` — первое
число, поэтому у ЛР 2 с `"2 (8)"` получается
`Лабораторная работа 2.pdf` — и вызывает `typst compile --root .`.
Никаких проверок, установок и правок исходников.

```bash
DIST=out ./build.sh                  # в другую папку
cd lr/2 && typst compile --root ../.. main.typ out.pdf   # одна работа
```

Python-пакет вместо CLI: `pip install --user typst`, `typst.compile(...)`.

## Структура

```
build.sh        ./build.sh -> dist/*.pdf (только компиляция)

lib/lab.typ     шаблон отчёта: setup(), report() — каркас пунктов 1–11,
                console() — текст из .txt (консоль, листинг, тесты),
                общие списки оборудования и ПО

lr/2/ lr/5/ lr/9/
                main.typ (только содержимое отчёта) + src/ + img/ + tests/
lr/template/    образец main.typ для новой работы
lr/6/           исходники без main.typ — в сборку не попадают

.github/
  workflows/    ci.yml (проверка сборки), release.yml (релизы с PDF)
  actions/      build-reports — общий шаг: Typst + шрифты + сборка
  scripts/      вся логика для workflow:
                  check-reports.sh   ссылки, номера, дубли (typst не нужен)
                  build-summary.sh   сводка dist/summary.md
                  install-typst.sh   Typst нужной версии
                  install-fonts.sh   Hack, Liberation, Times New Roman
                  check-fonts.sh     шрифты из цепочек lib/lab.typ на месте
                  release-assets.py  lab-reports.zip + ASCII-имена ассетов
```

`main.typ` каждой работы — это один вызов `report(...)`: в файле работы
лежат только отличия — номер, тема, цель, задание, содержимое пунктов 6–8
и строки дневника отладки. Номера пунктов, их названия, пояснения в
скобках, оборудование, ПО, списки «Допущен к выполнению работы»,
«Пункты 1–7 отчета составляются строго до начала лабораторной работы.»
и подпись живут в шаблоне.

## Как написать новую работу

```bash
cp -r lr/template lr/<вариант>
```

и в `lr/<вариант>/main.typ` заполнить содержимое:

```typst
#import "/lib/lab.typ": setup, report, console

#show: setup.with()

#report(
  number: "3",                     // номер ЛР -> имя PDF
  topic: [Тема работы.],
  goal: [изучение и освоение …],
  task: [(вариант № 1) …],
  // необщие строки ПО — к общему списку (по желанию):
  software-extra: (
    "Утилиты операционной системы: nam",
  ),
  idea: [                          // пункт 6
    #console("/lr/3/src/commands.txt")
  ],
  scenario: […],                   // пункт 7
  protocol: [                      // пункт 8
    *Сессия 1.*
    #console("/lr/3/src/session1.txt")
  ],
  diary-rows: (                    // пункт 9
    ("1", "дом.", "16.09.2025", "20:00", "Выполнение работы", "Нет", "Нет"),
  ),
  conclusion: […],                 // пункт 11
)
```

Пути в `#console(...)` и `image(...)` — от корня проекта, поэтому после
копирования шаблона их нужно поправить на свою папку. Общее ПО (`NixOS 26.11`,
`zsh 5.9.2`, `gcc 16.2.0`, `vscode 1.144.0`) и оборудование
(`Intel® Core™ i5-12400F`, `ОП 32 ГБ`, `SSD 1 ТБ`,
`Монитор 23.8" AOC 24G2SAE/BK`) меняются в одном месте — `lib/lab.typ`
(`default-equipment` / `default-software`), реквизиты шапки — там же
(`doc-meta`).

## Как что оформляется

| Элемент | В Typst |
|---|---|
| Поля 3 / 1.5 / 2 / 2 см, A4, 12 pt, нумерация | `setup(...)` из `lib/lab.typ` |
| Вся структура отчёта (пункты 1–11) | `#report(...)` в `main.typ` |
| Шапка лабораторной (заголовок + реквизиты) | внутри `report()` |
| Текст из `.txt` (консоль, листинг, тесты) | `#console("/lr/2/src/session1.txt")` |
| Картинка с подписью | `#figure(image("/lr/2/img/plot2d.png", width: 78%), caption: […])` |

Консоль, тесты и исходники — это просто `.txt`-файлы, скопированные из
терминала как есть. Никаких функций вида `test-case(...)` с массивами
строк и ручных отступов `#h(...)`: файл подключается одной строкой
`#console(...)` и печатается моноширинным шрифтом на светло-сером фоне —
как скопировано из консоли. Длинные строки переносятся по правому краю.

Текст отчётов лежит отдельно от оформления: чтобы поменять поля, кегль
или шрифт — правится один файл `lib/lab.typ`, тексты не трогаются.

## Шрифты

В репозитории шрифтов нет — `typst` берёт их из системы. В `setup()`
заданы цепочки с автоматической подстановкой, первая найденная гарнитура
используется:

* основной текст: `Times New Roman` → `Liberation Serif` → `DejaVu Serif`;
* консоль: `Hack` → `Liberation Mono` → `DejaVu Sans Mono`.

Цепочки — параметры `setup()` (`body-font:` / `mono-font:`). Ни одно
семейство из цепочки не найдено — `typst` подставит встроенные шрифты
(другой рисунок и толщина). В CI это исключено: шаг «Проверить шрифты»
падает, если в `typst fonts` нет `Hack`, `Liberation Serif` или
`Liberation Mono`, а настоящий Times New Roman ставится из
`ttf-mscorefonts-installer` — поэтому PDF из релиза набраны им.

## CI/CD (GitHub Actions)

Тот же `./build.sh` запускается в Actions: локальная и серверная сборки не
расходятся. Всё бесплатно — репозиторий публичный, используются только
официальные `actions/*` и системные утилиты, сторонних сервисов нет.

| Workflow | Когда | Что делает |
|---|---|---|
| `ci.yml` | push в `main`/`master`/`dev`, каждый PR, вручную | `check-reports.sh`, затем сборка PDF; артефакт `laboratornye-raboty`, таблица в Summary |
| `release.yml` | push тега `v*` | обычный релиз (Latest) с PDF всех работ |
| | push в `main`/`master` | релиз-сборка на этот коммит: тег `build-ГГГГММДД-ЧЧММ-<sha>`, prerelease (Latest не переключается) |
| | вручную | то же, что push в текущую ветку |

Порядок шагов одинаковый: проверка отчётов (`check-reports.sh`, без typst,
за секунду) → Typst → шрифты → `./build.sh` → сводка → артефакт/релиз.
Каждый этап — отдельный шаг лога, поэтому сразу видно, что упало. Всё
запускается на `ubuntu-24.04` явно, чтобы смена LTS в образе не ломала
сборку неожиданно.

К релизу прикладывается:

* `lab-reports.zip` — архив, внутри файлы с ровно теми именами, что в
  `dist/`: `Лабораторная работа 1.pdf`, …;
* `lab-1.pdf`, `lab-2.pdf`, … — те же PDF отдельными файлами (GitHub
  переписывает имена ассетов релиза в ASCII, поэтому кириллическое имя
  сохраняется в архиве и в подписи ассета);
* `summary.md` — таблица собранных работ;
* в теле релиза-сборки — та же таблица.

<details>
<summary>Что где настраивается</summary>

* версия Typst — `inputs.typst-version` в
  `.github/actions/build-reports/action.yml` (сейчас `v0.15.1`, качается
  официальный статический бинарник);
* шрифты — `.github/scripts/install-fonts.sh`: `fonts-hack`,
  `fonts-liberation`, `fonts-dejavu-core` и **настоящий Times New Roman**
  из `ttf-mscorefonts-installer` (multiverse, EULA принимается через
  `debconf-set-selections`, 3 попытки скачивания с SourceForge, между
  попытками `dpkg --configure -a`). Times New Roman обязателен по
  умолчанию; `inputs.require-times-new-roman: "false"` превращает его
  отсутствие в предупреждение, и текст набирается метрически совместимым
  Liberation Serif;
* релизы на каждый коммит в основную ветку — job `release` в
  `release.yml`; не нужны — уберите `branches:` из триггера `push`, и
  релизы будут только по тегам;
* проверки перед сборкой — `.github/scripts/check-reports.sh`: ссылки на
  файлы (`#console`, `image`), наличие `number:` и дубли номеров. Локально
  запускается так же и typst не требует.

</details>

Ручной релиз:

```bash
git tag v1.0 && git push origin v1.0     # -> GitHub Release v1.0 с PDF
```

## Что поправлено по сравнению с ODT

* длинные строки протоколов больше не уезжают за поле (в ODT они
  переносились как попало);
* списки оборудования/ПО — настоящие списки, а не табы;
* в ЛР 1 управляющие последовательности терминала (`^[[?2027...`) в одной
  строке протокола вычищены — осталась нормальная команда `cat f2.txt`;
* исправлены опечатки: «Тюрингита» → «Тьюринга», «Не нормированные
  алгоритм» → «Ненормированный алгоритм», «полиндромию» → «палиндром»,
  «в пунке» → «в пункте»; «Hellow world» оставлено как в исходнике (это
  вывод программы);
* в дневнике отладки ЛР 1 поправлена противоречивая запись про номер
  группы (в ODT было «не 133, а 133»).
