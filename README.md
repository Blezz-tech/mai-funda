# Отчёты в Typst — МАИ, каф. 806, «Фундаментальная информатика»

Четыре отчёта, перенесённые из ODT-файлов в Typst:

| Папка | Что это | Исходник |
|---|---|---|
| `kr1/` | Курсовая работа, задание 1 (машины Тьюринга, VTM) | `Курсовая Работа Маркусь Евгений Версия 1.odt` |
| `kr2/` | Курсовая работа, задание 2 (нормальные алгоритмы Маркова) | `Курсовая_Работа_№2_..._Версия_1.odt` |
| `lr1/` | Лабораторная работа № 1 (ОС UNIX) | `Маркусь Евгений ЛР 1 Версия 4.odt` |
| `lr2/` | Лабораторная работа № 2 (системы программирования на Си) | `Маркусь Евгений ЛР 2 (8) Версия 2.odt` |

## Сборка

```bash
./build.sh                  # собрать все четыре -> <папка>/out.pdf
cd lr1 && typst compile --root .. --font-path ../fonts main.typ out.pdf   # по одному
```

Нужен только `typst` (0.13+; проверено на 0.15.x). Если CLI нет в PATH,
`build.sh` автоматически использует PyPI-пакет `typst`
(`pip install --user typst`). `--root ..` обязателен,
потому что шаблон и шрифты лежат на уровень выше.

## Структура

```
lib/template.typ    всё оформление сразу на четыре отчёта:
                    страница, шрифты, титульный лист, шапка ЛР,
                    report() — весь каркас пунктов 1–11,
                    листинги, протокол с картинками, тест-кейсы, дневник отладки,
                    общие списки оборудования и ПО (default-equipment / default-software)
fonts/              Tinos (аналог Times New Roman), Cousine (аналог Liberation Mono), Arimo
kr1/ kr2/ lr1/ lr2/ main.typ (только содержимое отчёта) + src/ (листинги/протоколы) + img/ (рисунки)
```

`main.typ` каждой работы — это один вызов `report(...)`: в файле работы
лежат только отличия — тема, цель, задание, содержимое пунктов 6–11 и
строки дневника отладки. Номера пунктов, их названия, пояснения в
скобках, оборудование, ПО, списки «Допущен к выполнению работы»,
«Пункты 1–7 отчета составляются строго до начала лабораторной работы.»
и подпись живут в шаблоне.

## Как написать новую работу

```typst
#import "../lib/template.typ": *

#show: setup.with(body-size: 12pt)

#report(
  cover: "lab",                     // "course" — титульный лист курсовой
  meta: lab-meta,                   // или свой dict с реквизитами
  topic: [Операционная среда OC UNIX.],
  goal: [изучение и освоение …],
  task: [(вариант № 1) …],
  // необщие строки ПО — к общему списку (по желанию):
  software-extra: (
    "Утилиты операционной системы: nam",
  ),
  idea: […],               // содержимое пункта 6
  scenario: […],           // содержимое пункта 7
  protocol-body: […],      // содержимое пункта 8
  diary-rows: (
    ("1", "дом.", "16.09.2025", "20:00", "Выполнение работы", "Нет", "Нет"),
  ),
  conclusion-body: […],    // содержимое пункта 11
)
```

Общее ПО (`NixOS 26.11`, `zsh 5.9.2`, `gcc 16.2.0`, `vscode 1.144.0`) и
оборудование (`Процессор Intel® Core™ i5-12400F`, `ОП 32 ГБ`, `SSD 1 ТБ`,
`Монитор 23.8" AOC 24G2SAE/BK черный`) меняются в одном месте —
`lib/template.typ` (`default-software` / `default-equipment`).

## Как что оформляется

| Элемент | В Typst |
|---|---|
| Поля 3 / 1.5 / 1.25 / 1.25 см, A4, 12 pt, нумерация | `setup(...)` из `lib/template.typ` |
| Вся структура отчёта (пункты 1–11) | `#report(...)` в `main.typ` |
| Титульный лист курсовой | `#title-page((...))` (вызывается из `report()`) |
| Шапка лабораторной (заголовок + реквизиты) | `#lab-head((...))` (вызывается из `report()`) |
| Пункт отчёта «1. Тема: …» | `#item("1.", "Тема:", [...])` (вызывается из `report()`) |
| Общие списки оборудования / ПО | `#default-equipment` / `#default-software` (+ `software-extra`) |
| Листинг из файла, моноширинный | `#listing("/папка/src/файл")` |
| Протокол терминала с рисунками | `#protocol("/lr/1/src/session1.txt", images: (...))` |
| Описание теста (вход/выход) | `#test-case("Тест 3", "0 1 2", (...))` |
| Дневник отладки | `#diary(((...),(...)))` (строки — из `diary-rows`) |
| «Подпись студента ____» | `#signature()` (вызывается из `report()`) |

Текст отчётов лежит отдельно от оформления: чтобы поменять поля, кегль
или шрифт — правится один файл `lib/template.typ`, тексты не трогаются.
То же самое работает и для общих блоков: название любого пункта,
оборудование и ПО меняются один раз в `lib/template.typ`.

## Шрифты

Times New Roman проприетарный, поэтому используется **Tinos** — он
метрически совместим с Times New Roman (те же ширины символов), так что
вёрстка совпадает с исходником. Если в системе есть настоящий Times New
Roman — поменяйте в `setup()` `"Tinos"` на `"Times New Roman"`.

`Cousine` — метрический аналог Liberation Mono (моноширинные листинги).

## Что поправлено по сравнению с ODT

* длинные строки протоколов больше не уезжают за поле (в ODT они
  переносились как попало);
* списки оборудования/ПО — настоящие списки, а не табы;
* в ЛР 1 управляющие последовательности терминала (`^[[?2027...`) в одной
  строке протокола вычищены — осталась нормальная команда `cat f2.txt`;
* исправлены опечатки: «Тюрингита» → «Тьюринга», «Не нормированные
  алгоритм» → «Ненормированный алгоритм», «полиндромию» → «палиндром»
  (в ЛР/курсовых, где встречалось), «в пунке» → «в пункте», «Hellow world»
  оставлено как в исходнике (это вывод программы);
* в дневнике отладки ЛР 1 поправлена противоречивая запись про номер
  группы (в ODT было «не 133, а 133»).
